# 代码整理与验证

## 判断与修改

整理服务于可读性、维护性和项目一致性。规范格式、完整异常处理、类型标注、合理测试及常见设计模式不是应删除的 AI 痕迹。无明确收益时不改。

- 注释：清理逐字复述代码、聊天口吻及无信息量分节；保留设计理由、约束、单位、复杂算法、兼容说明和问题链接。
- 命名：用项目领域词汇替换误导性局部名称，先查引用，包括反射、序列化、插件注册和模板中的字符串。
- 冗余：边界明确时合并重复逻辑、去掉无用途转发层及可证明不可达代码；不为减少行数牺牲清晰度。
- 抽象：确认包装没有实际职责、扩展点和调用约束后才简化，命名与组织服从项目习惯。

保留类型忽略、lint/format 指令、覆盖率标记、编译指示、构建标签、文档生成标签、编码声明、shebang、源码映射及生成标记。保留许可证、版权和真实来源；遇第三方和生成标记返回范围判断。

## 注释精简重点

默认积极清理过长、过细的讲解式注释：删除逐行翻译、步骤播报、重复参数名或类型、与函数名等价的说明，以及简单函数上的大段模板 docstring。能从代码直接读出的内容通常不再解释；包含必要信息的长注释压缩到足以说明原因、约束或例外的程度，不设置统一行数或注释比例。

删除自有代码注释中装饰性的 emoji，包括标题、步骤编号和成功/警告图标；有实际含义的警告改成简短文字，不能连同风险说明删除。去掉无信息量的横幅、分隔框和“开始执行/完成处理”式注释。不能使用覆盖整份源码的 emoji 正则替换：字符串、测试样本、正则、用户界面及协议数据不属于注释清理范围。

保留复杂算法的推导、并发和安全约束、单位、兼容性原因及不明显的业务规则，即使它们较长。工具指令、许可证、来源声明及引用内容沿用保留规则。docstring 若被 doctest、文档生成或运行时读取，先核对用途，保留约定格式与可执行示例。

例如：
```python
# 🚀 第一步：检查重试次数是否超过最大重试次数
# ✅ 如果已经超过最大次数，就不再重试并返回 False
if attempts >= max_attempts:
    return False

# ⚠️ 供应商会重复投递，写入前必须按事件 ID 去重
```
可整理为：
```python
if attempts >= max_attempts:
    return False

# 供应商会重复投递，写入前按事件 ID 去重。
```

复查时确认：装饰 emoji 与冗余讲解已清理，必要约束、工具指令和字符串内容未误删。报告说明注释精简的代表性变化，不将注释少等同于质量高。

## 重构边界

保持公开符号、签名、返回结构、异常约定、CLI 输出、配置键及持久化格式。用户可见文案可能被调用方依赖，先查契约。保持求值顺序、异步行为、日志用途、边界值及副作用。

不借整理机会升级依赖、迁移架构或修复无关缺陷。需改变外部行为才能处理的问题先报告并取得范围授权。

例如：
```python
# This function processes the name and returns the processed name.
def normalize_name(name):
    processed_name = name.strip()
    return processed_name
```
在无额外约束时可改为：
```python
def normalize_name(name):
    return name.strip()
```
不额外加入 str(name)、None 默认值或 lower()，这些会改变行为。代码相似但业务语义不同的函数不必合并。

## 验证

修改前记录相关已有检查，区分既存失败和新失败。修改后运行受影响模块的测试、类型或静态检查。仅表达变化采用相称检查，不新增只断言措辞或内部实现的测试。

合并逻辑或调整控制流时，覆盖正常值、空值、错误输入及相关副作用；优先复用测试，缺关键覆盖才补有意义的测试。可在隔离工作目录对比前后行为，记录真实结果；示例通过不证明全项目等价。

运行未知项目检查前读入口与配置，不执行会发布、部署、清库、安装不明组件或访问生产服务的步骤。外部服务检查选本地隔离方式；无法隔离则记录未验证范围。

新失败归因于本次修改时修正或回退该项，保留其他已验证整理，不重置用户工作。无可运行检查时收紧到表达层和能审阅的简单局部修改，说明功能未充分验证。
