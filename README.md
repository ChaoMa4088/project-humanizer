# Project Humanizer

面向软著申报材料与软件项目包的 Codex 技能，重点精简冗长注释、清理装饰性 Emoji、改写模板化说明，并核对文档与代码。支持目录、ZIP 和指定文件，保留技术事实、真实来源、对外接口及功能。

## 主要能力

- 润色中英文 Markdown、TXT 和技术说明，核对文档与实现。
- 精简过长、过细的讲解式注释与模板 docstring，删除装饰性 emoji、横幅及重复步骤说明。
- 保留设计理由、业务约束、工具指令、许可证和真实来源声明。
- 允许有明确收益的局部重构，例如简化无用包装、整理命名和重复逻辑。
- Word 修改后要求检查排版；PDF 默认审阅并输出可编辑改写稿，有源文件时优先处理源文件。
- 交付变更报告，明确跳过项、待确认事实及实际验证范围。

这是供 Codex 读取的工作流技能，不是自动改写程序；不会凭风格判定作者，也不保证 AI 检测分数。Word/PDF 处理需要运行环境具备相应工具。

以一套工艺决策与指令生成软件的软著材料为例，对比原始包与整理后的 V2.0 包。以下数值于 **2026-10-19** 直接从当前源码重新统计，未使用 AI 检测器。

| 对比项 | 整理前 | 整理后 | 变化 |
| --- | ---: | ---: | ---: |
| Python `#` 注释处数 | 251 | 120 | 减少 52.2% |
| Python `#` 注释字符数 | 7,294 | 1,761 | 减少 75.9% |
| Python docstring 字符数 | 2,815 | 2,005 | 减少 28.8% |
| Python + HTML 物理行数 | 3,595 | 3,419 | 减少 176 行 |
| Python 文件数 | 13 | 13 | 保持一致 |

**把重复讲解压缩成必要说明，而不是把注释全部删掉。** 以下为真实文件节选，未改写示例原文。

### 1. 大段函数说明 → 一句概括

`core/expert_agents.py` 中的函数 docstring：

**整理前**

```python
"""【第三级降级 · Multi-turn CoT · 3轮深度推理】

Turn 0 — 零件特征解读：从材料体系、几何特征、结构角色三个维度分析零件，
          推导出该零件对本工序的约束条件，作为后续推理的事实锚点。
Turn 1 — 工序分析：以 Turn 0 的零件约束为依据，分析工序定性/要求/步骤，
          每条结论须引用 Turn 0 中的零件特征，禁止输出参数数值。
Turn 2 — 参数核查 + 反思：以 Turn 0+1 为上下文，逐一核查参数（已确认/需确认），
          并反思 Turn 1 是否存在遗漏、矛盾或依赖未确认零件信息的结论。
汇总结果作为 reference_knowledge 传给 JSON 生成链（即 Turn 3）。
"""
```

**整理后**

```python
"""依次分析零件约束、工序要求和参数，将三轮结果交给生成链。"""
```

### 2. 夸大保证 → 可核对的处理规则

`utils/instruction_gen.py` 中的注释：

**整理前**

```python
# 2. 终极防崩溃兜底：强制把超过 30 个连续且没有空格的字符切断，给 fpdf2 提供绝对安全的换行点
```

**整理后**

```python
# 每30个连续非空白字符插入换行点。
```

规则和数值保留，删除“终极”“绝对安全”这类没有验证依据的保证。

### 3. 说明书与实现对齐

原说明书把第三个评价维度描述为“文本丰富度”。整理后的说明书写为“D3 操作可执行性”，对应实际函数 `eval_d3_executability`，并解释编号步骤率、含数值率及操作动词覆盖率。整理不只换措辞，也核对文档在描述什么。

## 安装

仓库根目录就是技能目录，`SKILL.md` 无需移动。

1. 下载本仓库 ZIP 并解压，或将仓库克隆到本地。
2. 将包含 `SKILL.md` 的整个目录复制到 `$CODEX_HOME/skills/project-humanizer`；未设置 `CODEX_HOME` 时使用 `~/.codex/skills/project-humanizer`。
3. 如果同名技能已经存在，先备份再替换；不要覆盖其他技能。

Windows 的默认位置为 `%USERPROFILE%\.codex\skills\project-humanizer`。技能使用本身不需要安装 Python 依赖；下方仓库验证工具需要 Python 3.10 或更高版本。

## 使用

在能发现此技能的 Codex 会话中输入：

```text
使用 $project-humanizer 整理这个项目：<项目目录或 ZIP 路径>。
重点精简冗长注释并删除注释中的装饰性 emoji，允许局部重构，保持功能和对外接口，交付变更报告。
```

也可以指定部分文件或排除目录：

```text
使用 $project-humanizer 整理 README.md 和 src/，排除 src/vendor/。
保留必要的设计说明，只调整有明确问题的内容。
```

Git 项目默认原位修改并保留差异；无版本管理的材料及 ZIP 默认生成独立副本。第三方代码、依赖、构建产物、锁文件和自动生成文件默认跳过。字符串、界面文案和测试数据中的 emoji 不属于注释清理范围。
